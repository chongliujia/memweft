# 多步文件任务与外部存储对照（v2，实验前冻结）

## 问题与范围

v1 在完整当前事实、严格 JSON 单步答案和业务执行 guard 下三组均 30/30。本轮检验在需要自行补足资料、写入真实文件并执行可信程序时，历史策略是否影响任务正确率或工具成本。不是模型训练、真人外部开发者研究、任意代码生成或生产部署评测。

三个构造的可执行工作流（部署路由、账本导出、交接核验）分别覆盖 update、forget、delete/recreate、旧策略 rollback、无关来源更新：共 15 情境，每组都运行全部情境。相同模板的五种事件不是五个独立工作流。没有开发/测试泛化切分、没有多次模型采样，报告逐例结果和配对差异，不作统计显著性或真实用户收益声明。

## 对照合同

1. `plain`：SDK 普通文档持久化派生策略，无依赖检查。
2. `versions`：沿用 v1 的强 lazy 检查，包含继承依赖；源记录变化后读、采用和回滚时校验。顺序适配器不是完整原子并发协议。
3. `full`：实际 MemWeft learning API，事务内失效派生文档。
4. `mem0`：固定安装的 Mem0 OSS 原生 CRUD + 本地真实 embedding，以 `infer=False` 保存结构化源和策略、按确定 ID 读取。适配器维护 kind/key、JSON 序列化和活动指针。没有添加 MemWeft 的依赖失效逻辑；publication/rollback 是适配器操作，不是 Mem0 的原生功能失败。

内部机制消融与外部存储接入分开解释。外部组不评估 Mem0 语义抽取/相似度召回、图记忆或托管产品；结构化写入与显式读取是共同任务接口。安装版本、模型文件哈希、CRUD 操作和支持边界与输入一起冻结。外部实际操作不需要 Moonshot/OpenAI 抽取 API，不把本地 embedding 延迟当作模型推理费用。Graphiti 接入依赖核查不计作已执行对照。

各组使用相同任务、公开输入、当前来源工具、写入权限、模型与预算。只有检索到的派生策略不同。所有事件在新的模型会话开始前完成；不清理已经发给模型的历史消息，也不研究 mid-turn TOCTOU。初始输入不给当前完整 policy 或隐藏答案；模型自主决定是否调用 `read_source`。read_source 只暴露各组共同的 policy。读取工具使用各存储系统真实 CRUD 后冻结的来源快照，不宣称测量在线检索延迟。

## 实际工件和独立判分

`multistep_fixture.py` 定义公开项目文件、允许写入的配置、可信 router/exporter/receipt 程序，以及独立最终 oracle。生成的文件是真实磁盘工件；不执行模型提供的任意程序。

每次回复含最多三个顺序工具动作：批量读最多六个许可文件、读一个当前来源、原样写一个 JSON 文件、删除许可配置/生成文件以修正先前操作、运行可信程序。最多四轮，可提前结束。执行器只检查路径、JSON 类型和大小，不把业务错误值挡在落盘之前，不自动补字段或纠错。公开 smoke 只检查格式、输入引用和执行行为，不读取当前 policy 或 oracle。最终验收要求最后一次文件修改后有成功的公开 run，并检查实际配置和程序产物；撤回要求明确 blocked 工件及无发布输出。隐藏 oracle、逐轮判分和错误写入计数不返回给模型。

## 冻结、预算与完整日志

在第一次 API 调用前保存全部源码快照/SHA-256、原生库 SHA-256、15 个案例、60 组初始消息、只读工件哈希和外部依赖 manifest。种子 20261004 打乱案例，每例轮换四组顺序。冻结后源码/输入/native 不一致即拒绝执行。

Kimi `kimi-k2.6`，thinking disabled，JSON object，提供方采样默认值，每次最多 1024 输出 tokens。最多 240 次有响应的调用；累计已报告 500,000 tokens 时停止后续调用（可能超出最后一请求），请求文本不超过 64,000 UTF-8 bytes。价格估算按未命中缓存输入 ¥6.5/M、输出 ¥27/M；不等于账单。

请求串行、开始间隔至少 1.1 秒；实际账户等级未知。只有 HTTP 429 可对完全相同输入等待 60 秒后重试，最多两次；最多 720 次 HTTP 请求，429 独立记账。其他 API/网络错误停止并保留全部证据，不自动重复付费请求。已尝试过的目录拒绝再次 `run`；中断后的部分结果必须保留并另行说明，不静默拼接新实验。每个请求前记 attempts，响应先落盘再操作工具，随后记录完整工具结果、隐藏判分和最终工件哈希。无密钥落盘。
