# 私有来源失效与长会话查询加固

日期：2026-09-27。基线为 `ffec39be8c3c43809a566c82aaae56ae99a83550`，对照为本次工作区实现。
本轮覆盖来源正确性、消息窗口和文档查询；没有重跑模型评估或百万事实/WAL 压力测试。

## 修复与行为

- 私有事实更新和来源失效在同一个 IMMEDIATE 事务提交。依赖它的任务、历史策略和生效策略被失效，包含从基线继承的来源。相同值重写同样失效，低层 API 重命名事实或新增同 key 的另一 ID 也覆盖；失败写入保持原事实和策略。
- 私有来源沿用作用域级学习 generation，提交旧评估会冲突。回滚在读取待恢复版本之前固定 generation，防止并发更新后恢复旧版本。其他 Agent/用户/租户和无关已生效策略不受影响。同作用域无关的进行中评估仍可能因 generation 变化而冲突。
- 消息追加/重试和学习记录点查使用精确 namespace/key 查询。文档前缀在 SQLite 内过滤，私有和共享来源失效只读取 learning 文档。
- `context()` 在同一读事务内取最近 N 条消息及有界的最早排除 key 样本。保持原消息顺序、预算规则和最多 64 项诊断，不读取整段历史正文。
- 新增最近文档、learning 子集和私有 fact key 索引。首次打开旧数据库需要建索引，表布局和已有记录不变。全量 `messages()`、`memories()` 以及 LangGraph 通用过滤分页仍不是有界查询接口。

用同一组新增跨语言契约操作分别加载旧/新原生扩展：基线在私有来源更新后仍返回旧策略；本轮实现返回 null。该场景同时进入 Rust、Python、Node 契约回归。

## 长会话 SDK 对照

本机 macOS arm64、Python 3.11.5、Rust 1.89.0 release 构建。每种规模使用独立文件数据库：目标会话 N 条消息，同一用户另有 N 条消息分散在 100 个其他会话；另有一条事实和一个生效策略。`context()` 取最近 10 条并包含策略。每项操作测量 20 次，表中为 p50，单位 ms。

| 目标会话消息数 | context 旧→新 | active 旧→新 | 追加消息旧→新 | 幂等重试旧→新 |
|---:|---:|---:|---:|---:|
| 1,000 | 5.347 → 0.380 | 2.393 → 0.013 | 2.612 → 0.055 | 2.571 → 0.022 |
| 10,000 | 60.200 → 0.381 | 28.135 → 0.013 | 32.253 → 0.063 | 32.102 → 0.023 |
| 100,000 | 762.607 → 0.374 | 417.547 → 0.013 | 425.352 → 0.068 | 411.676 → 0.023 |

100,000 条时 context p95 为 777.304 → 0.418 ms。三组规模的完整 Context（text、memories、messages、strategies、report）SHA-256 均相同，不只比较前几个结果。

建库、SQL 夹具装载、索引创建以及一次 context 预热不计入请求延迟。追加测量期间每次创建一个新 event ID；重试固定重放已存在的 ID。使用同一 runner，旧版先运行、新版后运行；单客户端、热缓存、单轮，不是并发吞吐或生产 SLO。系统负载未隔离，20 个样本不能代表长期尾延迟。

索引有磁盘成本：在各 SDK 已关闭后装载数据，再重新打开并测量。100,000 条目标消息及同量其他消息的数据库文件为 68.43 → 84.79 MiB；不包含 WAL 峰值或首次建索引的临时空间。本轮没有测量既有大库的升级耗时，也不能由这些消息实验推导百万事实检索、WAL 回收或断电持久化保证。
