## 一项实际工具任务

新工具 `decision_log.py` 支持 `set/get/list/forget`，以项目、用户和键隔离记录，保存业务值及来源，
同键更新、重启读取、持久遗忘。它调用已安装 SDK 的公开 `Memory` / `UserMemory` 接口，
没有直接操作私有数据库表或另建 JSON 存储。数据分区依赖调用方可信身份绑定，不提供鉴权。

真实输入是从项目公开文档提取的三条约束：预览版分发方式、上下文完整性的含义、构建记录的证明范围。
实际 CLI 将它们写入 `task/data/project-decisions.db`，通过一次真实更新完善分发约束的措辞，
再从新进程读取。该更新是措辞细化，不代表项目历史政策变更。隔离、异常输入和遗忘测试使用独立的合成数据库。

| 阶段 | 观察结果 |
| --- | --- |
| 独立接入 | 安装、doctor、初始化成功；一次配置顺序错误后自行恢复 |
| 首次实现 | set/get/list 可用，base 25/25 通过；刻意留下 forget，任务仍 pending |
| 应用交接 | 保存目标、进度、环境、证据、真实账本及剩余工作，退出开发会话 |
| 新代理接手 | 补完 forget，完整验收 33/33 通过，跨进程读取的原三条账本记录一致 |
| 验收写回 | 应用再次运行冻结的完整验收器后，把任务写为 done，revision 从 1 变为 2 |
| 重启与重复完成 | 新进程恢复 done / passed；重复完成返回 already_completed，回执未新增或改变 |

新接手者从首次阅读到完成记录用时 372 秒，未请求前任补充提示。它曾额外探查不存在的
`Memory.forget`，出现一次 AttributeError；已输出的公开 `UserMemory.forget` 足以让它自行恢复。
这个失败与首次配置错误均保留在命令日志。时间仅是单次代理观测，不是人工接入速度基准。

规格、输入、验收器在实现前冻结；`verify.py` SHA256 为
`07858397be80eca9aa6430d3a600d65992d5b256a48a886f0c70332c242ae5b6`。
base 与 full 是同一任务的阶段；两次 full 是开发自查和应用验收，不计作两项新任务，也不将
33 个机器检查计作 33 个真实任务。源码审查补充验证公开 SDK 使用，黑盒检查本身不能证明存储实现。

## 暴露并修复的问题

1. **初始化顺序和目录说明不够明确。** 首次调用显式选择了尚不存在的配置，退出 1；代理随后先做
   无配置 doctor，再 init 和按配置 doctor，成功恢复。说明现明确 `app/` 与仓库目录的对应关系、
   当前工作目录以及配置必须先存在；修订后的四步序列已用固定 wheel 检查。
2. **交付包缺少简明的数据结构示例。** 已安装 wheel 的旧元数据没有说明 `memories()` 的完整返回形状；
   代理需要阅读已安装的公开 Python 接口并运行一个单独标记的合成探针。仓库新文档已有相关解释，
   但固定旧 wheel 未携带它。现将 `fact_key/value`、业务来源字段、整值替换和遗忘说明直接补入应用指南，
   随应用一起交付；示例写入、跨进程读取和遗忘已实际检查。
3. **英文模型建议被过窄的字符上限拒绝。** 原 Kimi 建议与剩余工作相符，正常结束，但下一步 194 字符、
   理由 121 字符，超过旧版 120/80 上限。现上限为 320/160，提示与校验共用常量，保留有限长度，
   不截断响应。严格 JSON、待办任务范围、256 输出 token 和无自动重试等约束保持。

新增离线回归重放了原始模型文本，覆盖中英文精确边界与超限拒绝；交接相关 **41 项测试通过**，
其中规划器 12 项。测试汇总来自代理已观察的会话工具输出，没有另存原始日志文件；证据中的
`planner-test-record.json` 明确这一限制。本轮没有重跑与此修改无关的完整 SDK 套件。

## 两次真实 Kimi 请求

模型验证作为独立分支进行：父代理只代为提供隐藏凭据，使用首次开发者已保存的同一待办状态。
新接手者没有读取任何 Kimi 输出，所以其开发结果不能归因于 Kimi 建议。修订后的真实复测在生产者
状态副本上执行，只替换 `planner.py`；原应用、原失败和参与者目录保持原样。

## 交付与结论边界

[机器报告](2026-10-02-cold-consumer.json)索引了原始及修订模型响应、两阶段工件、完整验收、状态恢复、
来源哈希和审查结果。原始证据在 Git 忽略的 `data/cold-consumer-2026-10-02/`；归档
`dist/memweft-cold-consumer-2026-10-02.zip` 保存修订应用、固定 wheel、实际工具和试验证据，不包含虚拟环境。
归档保留的历史命令含本机过程路径，移机重跑时需要新建环境并调整解释器路径；不要覆盖旧证据目录。

这次支持的结论是：固定 macOS arm64 / Python 3.11 环境下，一个小型顺序执行工具可以独立接入，
并经结构化交接由新代理继续完成。任务规模小、规格和验收器由协调者提供、遗留功能有意控制范围；
尚未覆盖完全无指导的真实开发者、持续使用、多项目并发或其他平台。下一步最有价值的是让实际外部开发者
用修订交付包完成自己的任务，收集首次接入阻碍和跨天继续工作的结果。
