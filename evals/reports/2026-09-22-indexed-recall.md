# SQLite 倒排检索落地与完整 SDK 实测

日期：2026-09-22。实现、回归测试与十万条存储压测已完成。Rust、Python、Node、CLI 共用新的 SQLite 检索路径，无需新增调用参数。此轮采用作用域倒排表、候选提前筛选和有限诊断；评分仍为原来的 `lexical_overlap_v1`，没有引入 BM25、WAND 或 Elasticsearch 服务。

## 完整查询延迟

以下是 **完整 Python SDK `Session.context()`** 的计时，包含 Rust 查询、正文加载、文本构造和 JSON 传输。每个查询预热一次后测 30 次；固定 `max_facts=10`、`max_tokens=1024`。旧版和新版 release 原生库在独立进程中读取同一语料的独立副本。

私有池和共享池各有十万条记录；混合池有十万条私有记录加十万条同名共享记录，使用 `private_first`，共享记录全部被遮蔽。所有 9 组的 `text`、`memories`、`messages`、`strategies` 均与旧版完全一致。

低频词、无命中和空查询的完整 SDK 延迟已降到几毫秒。高频词仍要聚合大量倒排记录，p95 约 171–174 ms；`LIMIT` 限制返回候选，不能免除这部分评分工作。这是下一轮适合研究安全上界剪枝的实际瓶颈。

这是单读者、热缓存、合成语料的观测结果。每种配置仅一轮，按旧版、新版顺序运行，未随机交错；旧版大报告的分配/回收也可能造成尾延迟波动。不能把这些 p95 当成线上 SLO，也没有验证百万条或高并发查询性能。

## 查询语义与诊断

- key 命中计 2 分、JSON value 命中计 1 分，使用相同 Unicode/中文双字分词；平分按 key、fact ID 排序，保留零分补齐。
- tenant、user、Agent、pool、私有事实有效期，以及池优先级都在 SQL 截断前生效，避免共享旧值因分数更高而重新出现。
- `conflict_policy=error` 保留全量冲突检查，即使冲突不在 Top-K 或 `max_facts=0` 也会报错。
- 写入、更新、删除和索引维护位于同一 SQLite 事务；候选、正文、遮蔽样本在一个读快照内完成。
- `max_facts=10` 时加载最多 74 条胜出候选；遮蔽诊断最多再加载 64 条落选正文。**74 不是索引访问次数**，报告中的 `index_entries_visited` 为 `null`。
- omissions、shadowed 各最多 64 条，报告提供截断标记；计数范围改为 `loaded_candidates`。依赖全量诊断的调用方必须适配。

私有低频词查询的 report 经 Python JSON 序列化，从 11,001,332 字节（10.49 MiB）降至 9,751 字节（9.52 KiB）。混合池对应从 22,001,329 降至 16,788 字节。候选检索和有限诊断共同贡献了完整 SDK 的性能改善。

第一轮实现还暴露了一个真实退化：混合池的零分补齐在所有共享键均被遮蔽时，仍扫描了整个低优先级池，低频词 p95 约 409 ms。最终实现使用已收集候选的最大 `(key, fact_id)` 作为后续池的 SQL 索引范围上界；超出该上界的记录不可能进入窗口，因此剪枝不改变结果。第一轮数据保留在 `data/evals/indexed-recall-comparison-run1/`，本报告统一使用最终 run2。

## 迁移、空间与写入成本

首次打开旧库会在一个事务中建立并回填版本 1 索引，后续打开复用它。这里的迁移时间包含首次打开；数据库文件大小在 checkpoint 后记录。

| 配置 | 新版打开及回填 / s | 旧文件 / MiB | 新文件 / MiB |
|---|---:|---:|---:|
| 私有池 | 5.55 | 25.85 | 132.57 |
| 共享池 | 5.10 | 70.05 | 128.29 |
| 混合池 | 9.35 | 70.05 | 261.80 |

共享测试语料由旧私有库转换而来，原文件含可复用空闲页；文件增长不能直接解释为所有索引页的大小。私有库约从 26 MiB 增至 133 MiB，索引空间是明确成本。

新增 90,000 条记录（从一万到十万）使用公开 SDK 逐条提交，最终耗时 588.95 秒，约 6.54 ms/条。此前独立存储压测对应为 102.97 秒，约 1.14 ms/条；这不是受控配对写入实验，但说明本次查询优化伴随明显写入成本，不能宣称整体读写性能都提高了。后续可独立评估批量事务和倒排存储压缩。

持久库升级必须同时升级所有写入端，并在接纳并发写入前完成回填。触发器依赖 SDK 注册的 `memweft_recall_terms_v1`；旧二进制或未注册此函数的 SQLite 连接在插入/更新事实时会失败。不能只回滚可执行文件而继续写已迁移的库。升级前保留正常数据库备份。本轮只修改隔离测试数据库，没有迁移业务库。

存储测试在配对基准结束后独立运行，没有与其计时重叠。100 到 100,000 条各测 30 次 `deployment port` 查询，均正确返回目标事实、满足上下文预算和候选/诊断上限；关闭重开后仍有十万条记忆。

写入列为各增量阶段耗时，第一阶段写 99 条，其后为 900、9,000、90,000 条。RSS 是包含此前测试的进程累计峰值，不是一次查询的增量内存。

- 8 个客户端、100 轮 CAS：800 次尝试，100 次成功、700 次预期版本冲突，最终值 100、revision 101；尝试耗时 p50 1.11 ms、p95 3.22 ms（包括冲突，不能当成纯成功写入耗时）。160 次重复消息提交只保存 1 条。
- 100 组 tenant/user、每组 2 个 Agent：私有记忆和会话泄漏为 0，200 次只读池修改被阻止。这验证应用绑定的作用域，不提供对任意数据库客户端的身份认证。
- 子进程确认提交 50 条后被 SIGKILL，50 条全部恢复，SQLite `integrity_check=ok`。使用 WAL、`synchronous=NORMAL`；没有模拟断电。
- Rust 34 项测试通过，其中包含 900 个完整候选差分组合；覆盖池顺序、Agent、中文/JSON/空查询、Top-K、有效期、同名事实、迁移回滚、CAS、删除重建和并发读快照。
- Python 12 项通过、2 项外部 Postgres/MySQL DSN 测试未配置而跳过；Node 6 项通过，TypeScript 构建通过；离线评估工具 37 项通过。
- 既有 36 个记忆及攻击场景重建后的模型输入文本逐字一致。本轮没有重新消耗模型 tokens，也不声称修复了此前发现的历史消息注入或业务标签错误。
