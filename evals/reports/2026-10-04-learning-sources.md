# 学习来源点查与失效反向索引

2026-10-04。基线为 `9029727`；对照为本轮来源索引实现。两组使用同一份 Rust runner、
Rust 1.89.0 release 构建，在 macOS arm64 本机顺序运行。无模型调用。

本轮只改善学习生命周期的存储路径：来源检查从枚举事实改为按键查询，失效发现从扫描学习
文档改为按来源查找派生文档。来源声明、继承、评测门槛、版本检查和事务边界没有改变。
这不是新的一致性协议，也不证明模型任务正确率提升。

## 条件与计时

每个独立文件数据库有 N 条私有事实、N 条共享事实和 N 条无关学习文档。无关文档各声明一条
私有和一条共享依赖。分别测量私有/共享来源的学习任务启动、带两条依赖的文档插入，以及
影响 8 条 active 文档的来源更新；另测 N=10,000、影响 1,000 条文档的场景。

每项一次预热、20 次计时。`start` 调用真实 Rust Learning API，包括保存 pending job；
更新调用真实 Store API，包括事实/检索索引写入、派生失效和提交。文档插入是构造的存储
操作，不是完整策略采纳。种子装载、受影响文档重建、逐次结果检查和最终完整性检查不计时。
每组事实规模的 start 在大量无关学习文档装载之前测量，以隔离事实枚举成本。

SDK 使用默认 SQLite 自动 checkpoint；没有移除较慢样本。热缓存、单客户端、每种构建各一轮，
顺序非随机，本机负载未隔离。20 个样本不支持长期尾延迟或统计显著性结论，不能将更新耗时
当作多写者吞吐或模型端到端延迟。

## 规模增长与低影响数量

单位 ms，下表为 p50，旧 → 新；来源更新影响 8 条文档。

| N | 私有来源 start | 共享来源 start | 私有来源更新 | 共享来源更新 |
|---:|---:|---:|---:|---:|
| 1,000 | 0.830 → 0.080 | 1.084 → 0.082 | 1.561 → 0.370 | 1.492 → 0.299 |
| 10,000 | 8.224 → 0.079 | 12.318 → 0.085 | 16.034 → 0.347 | 16.516 → 0.301 |
| 100,000 | 88.003 → 0.077 | 127.914 → 0.092 | 155.066 → 0.343 | 164.312 → 0.298 |

N=100,000 时，私有/共享 start 的新 p95 为 0.101/0.129 ms，私有/共享更新的新 p95 为
0.418/0.337 ms。结果支持“此夹具中不再随无关记录数线性增加”的判断，不支持常数时间保证。

## 代价与没有明显改善的场景

| 指标 | 旧 | 新 |
|---|---:|---:|
| N=100,000，带依赖文档插入 p50 | 0.031 ms | 0.102 ms |
| 同上 p95 | 0.055 ms | 0.451 ms |
| N=100,000，关闭后的数据库 | 209.94 MiB | 242.09 MiB |
| N=10,000，影响 1,000 文档，私有更新 p50 | 24.998 ms | 25.017 ms |
| 同上，共享更新 p50 | 26.244 ms | 24.423 ms |

十万规模夹具增加约 15.3% 数据库体积。依赖提取、索引维护和删除边的成本转移到了文档写入。
当受影响文档很多时，实际失效写入仍然昂贵，本轮没有显著解决这一问题。索引查找只避免解码
无关文档，仍会一次加载全部受影响文档；没有新增内存硬上限。

## 升级与语义核验

对基线十万规模数据库先作 SQLite backup，再使用新 SDK 打开副本。第一次打开包含 SDK
初始化和反向索引回填，耗时 780.31 ms；第二次打开 12.05 ms。回填生成 200,042 条依赖边，
文件从 209.94 MiB 增至约 242.04 MiB。计时不含关闭；大小在进程退出后读取，不代表迁移期间
临时/WAL 峰值。此观察只有一个副本、一次迁移。

四组旧/新夹具在移除文档创建/更新时间后，全部权威事实、共享记录和文档的 SHA-256 相同。
迁移副本在保留时间戳的逐行比较中也完全相同。每次更新检查受影响 active 值为 null，
无关记录保留；最后检查 pending jobs 已失效、全部无关文档仍在、数据库和外键完整性通过。

新增测试包括递归来源扫描/索引集合的 42 组对照（跨私有/共享、作用域、嵌套、重复、转义及
非标准字段形状），替换/删除/CAS 失败回滚、缺失函数时写入失败、迁移失败原子回滚、未来版本
拒绝、索引点查不解码无关文档，以及两个文件数据库实例上的共享更新/采纳/回滚并发。
原有私有更新、继承依赖、删除重建、跨作用域和并发回归继续执行。

本机验证：Rust 全量 72 项通过；重建原生扩展后的 Python 33 项中 31 项通过、2 项外部
数据库 DSN 测试跳过；TypeScript 构建和 Node 8 项通过；离线评估 246 项通过。
这些数字不代替后续提交对应的跨平台 CI，也不包含模型请求。

兼容性复核还确认：SQLite 会在判断触发器的 namespace 条件之前解析函数，旧 SDK/裸连接
对普通消息文档的写入也会因缺少函数而失败。历史长会话基准的裸 SQL 消息装载器已注册一个
仅允许消息夹具的受限函数；应用仍应通过 SDK 写入。修订装载器使用新原生 SDK 完成 1,000 条
目标消息及同量其他会话消息的冒烟验证，不将该短检查作为新的性能结论。
