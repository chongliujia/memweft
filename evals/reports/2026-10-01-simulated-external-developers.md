## 接入摩擦与交接质量

本轮没有发现阻塞任务完成的 SDK 功能问题，但保留了以下实际观察：

1. 系统默认 Python 3.9 与该 wheel 不匹配，需要显式选择 3.11。模拟开发者自行完成选择；
   这支持增加安装前检查，不能解释成 SDK 安装失败。pip 缓存权限和 shell 启动告警均不影响安装。
2. 工作日志开发者需要从公开应用示例和一次 SDK 探测了解 `memories()` 的 `fact_key/value` 结构。
   已在 [Python 文档](../../python/README.md#read-structured-facts)补充可运行示例，并在固定 wheel 环境
   执行了该代码块，输出符合预期。同时说明外层记忆状态、应用任务状态和必需记录完整性是不同概念。
3. 备份交接没有明确完成状态应该写回哪里。接手者选择自己的恢复库，记录原因，并保留原库与备份。
4. 工作日志交接把两个工作项都称作“新任务”，其中一个实际已经存在。接手者先查询当前状态，
   更新已有项，只创建缺失项。两处歧义都没有阻塞完成，但说明交接应明确状态写入目标并核对当前任务状态。

恢复遗忘前的历史备份确实会带回旧内容。备份后的逻辑核验因此不可省略；当前库的 `forget`
不会清除历史备份或导出。工作日志仍只承诺顺序 CLI 使用，没有验证并发读改写和长期历史增长。

## 可据此推进的改进

- 将平台、解释器和交付身份核验整理成安装前检查入口；本轮已有可运行下游工具可供评审。
- 给交接增加项目配置，明确数据库、scope、必需记录与完成状态写入目标，减少长命令及绝对路径。
- 在续接前核对任务是否已存在及当前状态，避免把“记录恢复完整”当作“任务状态仍然最新”。

这些是本轮证据支持的改进方向；除公开 SDK 文档补充外，本轮没有把下游试验工具升级为 SDK 的
正式支持接口，也没有改动 SDK 运行时。
