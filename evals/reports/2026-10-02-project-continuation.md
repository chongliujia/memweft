# 项目续接应用实测

2026-10-02：独立 Python 交接应用已接通项目配置、环境检查、当前任务恢复、Kimi 建议和验收写回。
在仓库外的新虚拟环境中完成三项新的工具开发任务；三项均由应用运行冻结验收器后写入 `done`，
新进程恢复均识别为已完成，重复完成命令未重跑验收。这个结论不等于真人验收或生产可靠性认证。

## 应用变化

[使用指南](../../examples/handoff_app/README.md#配置项目并继续真实任务)包含可复制的命令：

- `init` 用相对路径绑定数据库、工作目录、身份、必需记录与输出目录；配置不含凭据，不接受临时身份覆盖。
- `doctor` 检查解释器、原生 SDK 临时读写和配置，SDK 缺失时也能给出诊断，不调用模型。
- `task add/list/reopen` 使用明确任务 ID 和版本；`resume` 从当前 SDK 数据库恢复事实和任务，区分缺失与预算排除。
- `resume --model kimi` 只提出下一步；缺信息、证据变更或所选任务全部完成时在本地结束。
- `task complete ID --revision N` 运行登记时冻结的可信 Python 验收器，检查交付文件、配置与记录未变化，
  先保存日志及回执，再写入完成状态。后续恢复检查交付文件、验收脚本、回执及日志的哈希。

初版检查中发现并修复了 Windows 回执路径不兼容、过期提案在两个输出中状态不一致的问题，
并补充回归。原始模型候选明确标为尚待状态复核；最终 `planning.json` 和 `attempt.json` 一致。
共享 Kimi 客户端从旧示例抽出，旧导入入口保持可用；未来评测的源码指纹包含新客户端，历史单文件
客户端的真实证据仍可验证。此轮没有修改 SDK 运行时。

## 三项新交付

| 工具 | 真实输入与结果 | 冻结机器验收 |
| --- | --- | --- |
| 文档链接检查 | 扫描原交付子集的 18 篇 Markdown，发现 77 条缺失链接、0 条越界；其中包含子集未附带的仓库文件 | 8/8 用例通过 |
| API 用量汇总 | 解析 12 条历史真实调用：4818 输入、426 输出、5244 总 tokens；未知用量 0 次 | 54/54 检查通过，24 个子进程 |
| 交接导出审计 | 检查 5 份历史导出：3 份完整，1 份缺失必需记录，1 份因预算排除必需记录；任务仍 todo 不妨碍记录结构完整 | 6/6 用例通过 |

这三份 `solution.py` 在规格冻结后实现。60 个规格、输入、验收器文件在准备目录与执行目录两份均
逐项校验不变。工具处理的是实际历史输入，但旧 API 调用、旧交接及合成边界用例不计作新任务。
文档和交接审计对上述真实输入返回 1，表示发现问题；这符合工具合同，验收器自身返回 0。
交接审计工具此版面向历史的 facts 或 tasks 单一结构，不宣称支持新增应用的混合结构快照。

执行流程为：固定 wheel 安装 → 初始化与登记 → 进程退出 → Kimi 续接 → 实现工具 → 保存实际进度 →
再次 Kimi 续接 → 应用重新运行验收并写回 → 新进程恢复 → 重复完成检查。实现和接手均由助手完成，
外部人类参与和本轮人工评估均为 **0**。该过程证明受控任务可以继续和验收，不证明 Kimi 独立完成了开发。

## 真实 Kimi 调用与纠正

共 **7 次实际请求、7 个不同响应 ID**：3 次接手前、3 次实现后的待写回状态，以及 1 次提示修正后的复测。
均使用 `kimi-k2.6`、关闭思考、最多 256 输出 tokens，无自动重试、请求错误或截断。
发送内容逐项匹配调用前冻结的事实与任务投影，不发送源码、验收日志、环境变量或数据库绝对路径。

7 个回答均通过结构校验，但不能据此称为语义全对。交接审计的第一个待写回回答额外要求验收截图，
当前应用没有该要求。原回答完整保留，随后让应用为当前任务生成完整的带版本完成命令，并说明验收器
会自动保存证据。一次新的真实回答给出 `task complete handoff-audit --revision 1`，没有再次索要截图。
这是一次观察到的纠正，不是对未来回答的语义保证；自然语言建议仍需判断，应用不执行模型文字。

完成后的三次恢复由本地状态检查返回 `completed`，模型请求数为 0；它们不额外计作模型成功样本。
三轮真实请求使用的应用源码分别保存为 `planning-app/`、`checkpoint-app/`、`final-app/`，
各阶段哈希保留在 `installation.json` 与快照中，不把不同版本的调用合并成同版对照实验。

- 总用量：**2933 输入 + 379 输出 = 3312 tokens**。
- 模型请求时延中位数 **1.949 秒**，范围 1.752–2.765 秒，不含节流等待或任务开发时间。
- 按此前在北京时间 2026-10-02 核对并冻结的[官方价格](https://platform.kimi.com/)：每百万未缓存输入
  ¥6.50、输出 ¥27.00，估算 **¥0.0292975**。忽略缓存折扣；这是用量估算，不是账单。
