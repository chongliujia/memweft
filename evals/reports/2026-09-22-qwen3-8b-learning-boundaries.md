# 学习边界与泛化：验收改善，最终测试仍有退化

本轮实现并实测了边界训练、训练内有限修订和逐标签条件规则。**获得了一个通过原采用门槛的候选，但最终独立测试出现单题退化，因此“稳定可采用的改善”尚未达标。** 不能只用总体通过数上升来判定学习成功。

本机 `qwen3-8b`，温度 0、seed=42，回答使用固定 JSON Schema。共运行四个完整流程，**1,149 次真实模型调用**；每个测试条件重复两次。所有流程使用独立 SQLite 数据库，调用真实 Rust 学习接口，保留原始请求、响应和严格评分。

## 实现

- `common-v4`：训练从原来的 3 个正例扩充到 12 个例子，包含普通咨询、本人操作、已解决事件等边界。新建 12 道验收题、18 道最终测试题；13 个原有记忆控制场景保持不变。
- `boundaries`：要求候选明确适用任务、条件、例外和默认行为，分开判断队列与紧急程度。
- `boundaries_refined`：最多三轮“提案 → 训练集自检 → 训练反馈修订”。按训练通过数选候选，同分取较早版本；验收失败后不重提案。
- `grouped_rules`：按训练中观察到的五种 `(queue, priority)` 标签分别生成 `when` 和 `unless`。每条看到该标签的正例和其他标签的反例；输出标签来自训练标注，条件由模型生成。最多两轮训练内检查后，编译为一条任务策略。
- 增加训练轮次记录、最终测试逐题配对、泛化检查报告，以及非目标任务不注入策略的检查。

Rust 的采用门槛保持不变：平均增益至少 0.05、严格正收益、每个验收观察均不得退化，并满足成本和延迟限额。这里实现的是本地 Agent 评测中的可复用提案流程；没有更改模型权重，也没有把它设为 SDK 自动运行的学习服务。

## V4：增加边界样例和提示词仍不够

两组使用相同新题、核心二进制、runner 和模型设置，已核对哈希。下表的 24 次验收观察来自 12 道题各重复两次。

| 方案 | 基线通过 | 候选通过 | 退化观察 | Rust 决策 |
|---|---:|---:|---:|---|
| 原 3 个正例 + 原提案提示 | 12/24 | 12/24 | 8 | rejected |
| 12 个边界例 + 条件规则提示 | 12/24 | 18/24 | 2 | rejected |

被拒绝后最终测试继续使用原基线，均为 24/36，没有强行启用候选。扩充训练和改变提示词同时发生，这个对照不能拆分两者的各自贡献。

## V5：训练修订与逐标签规则

V4 已成为开发证据，V5 保持训练数据不变，重新建立验收和最终测试题。训练内整段修订的得分为 18/24、20/24、20/24；它仍把本人身份核验和安全咨询混为一类。

逐标签方案是在检查上述**训练结果**后确定的，其实现和测试固定时尚未读取 V5 验收／最终测试的评分或答案。两个 V5 流程的 runner 修订不同，因此没有把它们当作相同代码的严格消融实验；下面每行都使用各自同轮的学习前基线。

| 方案 | 验收基线 → 候选 | 验收退化 | 决策 | 最终基线 → 实际启用策略 |
|---|---:|---:|---|---:|
| 整段规则，训练内最多三轮修订 | 18/24 → 20/24 | 2 | rejected | 30/36 → 30/36 |
| 逐标签条件规则 | 18/24 → 22/24 | 0 | accepted | 30/36 → 32/36 |

逐标签方案的训练得分为第一轮 22/24、第二轮 20/24，按事先设定的规则选中第一轮。训练尚有错误，不能称为已经拟合所有训练边界。

最终独立测试的逐题变化：

- 两道“已成功付款但权益未到账”题改善，两次重复共 **4 次失败变通过**。
- 一道“本人用新设备登录、无可疑访问”的题，从正确的 `account/P2` 变成 `security/P2`，两次重复共 **2 次通过变失败**。
- 另一道包含“不是咨询付款方式，而是成功付款后未交付”表述的题仍输出 `billing/P2`，未达到预期 `billing/P1`。

按独立题目计，是 **15/18 → 16/18，2 道改善、1 道退化**。最终报告中的 `generalization_check.passed` 为 **false**。这个检查只报告最终迁移结果，不参与候选选择，也没有把测试答案反馈给提案器。

## 隔离、回滚与解释范围

- 被拒绝的候选没有进入最终上下文；被采用候选进入了对应任务上下文。
- 非目标任务未注入分流策略。
- 最终测试后，已实际调用 Rust rollback 并确认上下文恢复原基线。没有将候选发布到真实 Agent 项目。
- 逐标签运行的 186 次最终回答均符合输出协议，内容错误没有被字段修正掩盖。
- 原有记忆控制场景中，memory 与 memory_learning 均为 24/26；两次失败来自刻意关闭 query 的召回对照，与本轮学习无关。
- 26 项离线测试通过，覆盖训练／保留集分离、修订次数上限、候选选择、规则标签来源、对照一致性，以及“均分提高但最终单题退化仍判失败”。

这些是同一客服业务内的合成规则迁移测试，不代表跨领域泛化。两次温度零重复不是独立样本，不能用作统计显著性证据。逐标签候选仍存在语义重叠的规则；“按标签拆分”没有自动保证排除条件正确。

本阶段已补上可重现的训练修订与泛化检验流程，但尚未达到可靠自动采用的目标。下一轮应先解决训练中的规则交叉与否定条件表达，再使用新的独立保留集验证；本轮 V5 不应继续作为调参后的新证据。自动对话记忆提取和数据库候选检索优化不在本轮变更中。
