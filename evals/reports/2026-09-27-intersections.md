# 双词检索的有序分块交集

日期：2026-09-27。基线为 `281e0ebd18b2588120ae3c7b0e79e6caa9d4d133`，对照为本轮工作区实现。
优化沿用 v2 索引和原排序规则，无数据库迁移。30 组完整 Context 对照全部一致。

本报告保留中间 v2 实现的测量结果。当前代码已使用 v3 精确位图索引，
包含数据库迁移和额外写入、空间成本，见[后续对照](2026-09-28-bitmap-recall.md)。

## 改动与适用范围

原来的双词竞争交集以一侧 posting 为外层，对每个 ID 查找另一侧。
现在按固定作用域、词项和权重读取有序 ID，每侧缓存最多 256 项；
当两侧 ID 不等时，把落后的一侧推进到另一侧的 ID，允许直接跳过不相交的区间。
所有读取和最终记录筛选仍处于同一 SQLite 快照中。

仅当原有前缀证明成立时使用这条路径。作用域、记忆池优先级、有效性、
权重及相同分数时的排序规则不变。候选并集超过 2,048 项立即回退到完整聚合，
不通过截断交集近似返回结果。只改变交集枚举过程，不增加索引或公开选项。

交错分布仍需要遍历大量 posting；连续区间或极不均衡分布能跳过更多 ID。
这不提供次线性的最坏情况保证，三词以上、大交集和严格冲突策略仍有慢路径。

## SDK 实测

本机 `macOS-26.5.2-arm64-arm-64bit`、Python 3.11.5、Rust 1.89.0 release。
测量真实 Python `context(query="red blue", max_facts=10, max_tokens=4096,
include_messages=False)`，包含原生查询、正文读取、渲染和 Python 对象转换。
每项一次预热、10 次计时；单位 ms。p95 使用最近秩，在 10 个样本中等于最大值。

| 可见事实数 | 分布 | p50 旧→新 | p95 旧→新 | p50 倍率 |
|---:|---|---:|---:|---:|
| 100,001 | 交错、几乎不相交 | 23.167 → 18.002 | 23.621 → 18.922 | 1.29× |
| 100,001 | 连续区间、几乎不相交 | 21.386 → 1.896 | 22.309 → 2.089 | 11.28× |
| 100,001 | 偏斜分布、几乎不相交 | 40.045 → 1.874 | 40.868 → 1.966 | 21.36× |
| 100,001 | 大交集，精确聚合回退 | 182.925 → 178.629 | 184.876 → 181.112 | 1.02× |
| 1,000,001 | 交错、几乎不相交 | 217.993 → 166.643 | 285.978 → 168.198 | 1.31× |

10 万条夹具在同一数据库内放置四个独立用户作用域，每个包含 100,000 条普通事实和一条末尾双词匹配。
交错分布的 red/blue 单词记录交替插入；连续分布各占前后半段；
偏斜分布只有末尾 128 条普通事实包含 red，其余包含 blue。
大交集分布在前 200 条单词记录后全部包含 red 和 blue，强制触发精确聚合回退。
百万条实验单独建库，只测交错分布及对照查询。

另测 blue、common、unique、missing 和空查询，覆盖普通/高频单词、稀有词、无匹配和 key 排序。
这些对照的 p50 约 0.7–1.5 ms，没有显示出系统性变慢。
完整结果与尾延迟波动保留在原始 JSON 中；10 个样本不适合推断长期尾延迟。

新增 36 次与全量排序 oracle 的对照覆盖 255/256/257 和 511/512/513 长度附近的分块，
无交集、末尾匹配、长 ID 间隔，以及更新/删除后 ID 顺序与 key 排序不一致的情况。
原有测试继续覆盖混合记忆池、权重、遮蔽、并发更新快照和超过候选上限的回退。

建库、原生索引回填、完整性检查和数据库哈希计算在计时之外。
两版分别由独立进程串行运行，旧版先、新版后；不与其他测试或构建故意并行。
这是本机热缓存、单客户端、单轮测量，系统负载没有隔离。
本轮未测并发吞吐、WAL 空间回收、冷缓存或其他操作系统，也未重跑模型评估。
大交集回退的约 183→179 ms 应视为基本持平；不能把特定分布的 11–21 倍收益推广到全部查询。
