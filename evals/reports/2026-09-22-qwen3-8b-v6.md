# Qwen 学习边界：保留案例证据后通过本轮泛化检查

本轮决策表策略在新的独立测试中从 **34/48 提高到 48/48，无单题退化**；验收为 **24/36 → 36/36**，保持原有采用门槛。相同数据上的模型生成规则对照也通过验收，但最终为 44/48，仍有一道题退化。

这完成了本轮“在受控客服场景中获得可采用且通过独立测试的改善”的验证。它属于基于标注案例的上下文学习，不是模型权重训练，也不是已经证明开放任务或跨领域的稳定泛化。

## 改动与数据

此前生成器曾把安全咨询写入 `account` 规则，生成条件与原训练标签相矛盾。本次新增 `evidence_table`，按确定输出分组保留原始训练案例，直接形成可审计的决策表，不让模型改写业务条件或输出标签。运行时仍由 Qwen 根据当前问题进行类比判断；评分器没有补字段、填答案或改写模型回答。

候选先逐条对比训练基线，任何训练退化都会通过真实 Rust `learning_cancel` 取消任务，跳过独立验收，保持原策略。通过训练检查后，Rust 仍要求平均增益至少 0.05、每个验收观察无退化，并满足成本和延迟限制。训练检查通过不等同于通过独立测试。

V6 数据在模型调用前固定：

- 18 道训练题：原 12 题，两个明确标记为已退役的 V5 测试失败案例，另加四个边界案例。
- 18 道新验收题、24 道新最终测试题，所有表述均与 V1–V5 不同。
- 包含成功付款但未交付、未扣款、急需发票但服务正常、正在盗用、仅担心未来风险、本人登录、历史事件已解决和再次发生等对照。

旧保留题进入训练后不再作为新证据。两种方法使用相同的 V6 训练、验收和测试数据，没有根据本轮保留题的评分再次生成或挑选候选。

## 同轮结果

本机 `qwen3-8b`，温度 0、seed=42，固定 JSON Schema，每个条件重复两次。共 **581 次真实模型调用**：生成规则组 293 次，决策表组 288 次。使用 `--learning-only`，本轮没有重跑独立记忆控制场景，也未把旧结果混入统计。

| 指标 | 模型生成条件规则 | 保留标注案例的决策表 |
|---|---:|---:|
| 训练通过 | 36/36 | 36/36 |
| 验收基线 → 候选 | 24/36 → 36/36 | 24/36 → 36/36 |
| 验收单题退化 | 0 | 0 |
| Rust 采用决策 | accepted | accepted |
| 最终基线 → 已采用策略 | 34/48 → 44/48 | **34/48 → 48/48** |
| 最终改善观察 | 12 | **14** |
| 最终退化观察 | 2 | **0** |
| 本轮泛化检查 | 未通过 | **通过** |
| 最终输出协议合规 | 144/144 | 144/144 |

按独立题目计，决策表为 **17/24 → 24/24**，7 道题改善，0 道退化。两次温度零重复不能视为 48 个独立样本。

对照组在“急着报销、下载发票，权益交付正常”这道题上发生退化，两次重复均失败。决策表在本轮的本人设备验证、安全防护咨询、否定表达和已解决事件题目上均通过。训练和验收满分并没有保证对照组的最终正确性，这也是保留独立测试的必要性。

## 成本与限制

决策表保留了更多上下文。最终学习组平均每次调用的服务器总 tokens 为 **935.6**，生成规则组为 **645.1**，增加约 **45%**；同轮仅记忆基线为 **268.9**。两组全流程分别消耗 153,612 和 124,937 tokens。它们不是货币成本，且包含不同的提案开销。

策略文本约 2,866 UTF-8 字节，仍能装入现有 2,048 估算 token 的上下文预算。本轮只使用 18 个训练案例；大规模案例检索、压缩后是否保持决策边界尚未验证。

两组的 fixture、Rust 二进制、runner、输出契约、决策表模块哈希、模型参数及采用政策均已核对一致。两种 profile 同时改变了策略表示和训练退化检查，未单独分解两者的因果贡献。这是一个有限、合成、同领域测试集，不应把满分理解为生产可靠性保证。

## 实际生效、隔离与回滚

两种候选都实际进入对应任务的 Rust 上下文；非目标任务没有注入策略。最终测试后均调用 Rust rollback，确认上下文恢复学习前基线。试验数据库与真实 Agent 数据分开，未在真实项目启用候选。

31 项离线测试通过，新增覆盖：

- 决策表保留原始标签、拒绝同一输入的冲突标注。
- 训练检查必须与基线逐条配对，不允许缺项、重复或以平均改善掩盖退化。
- 训练退化触发实际学习取消流程，不提交虚构的验收分数。
- V6 保留题与旧版本无重复，旧测试转训练的来源明确记录。

本轮改动集中在评测提案流程与检查工具，没有开启 SDK 自动学习、自动事实提取或修改数据库检索路径。下一步可以把这一有证据约束的学习方式接入真实 Agent 工作流，再验证自然产生的训练反馈与上下文成本。
